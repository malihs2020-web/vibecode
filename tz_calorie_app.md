# Калькулятор калорий — техническое задание

Документ собирает уже реализованную функциональность и новые требования, согласованные в ходе обсуждения. Предназначен как референс и как контекст для AI-агента (Cline) при дальнейшей разработке.

## Стек и архитектура (уже реализовано)

- Frontend: React + TypeScript + Tailwind CSS + shadcn/ui
- Хранение данных: localStorage браузера, без бэкенда и без аккаунта
- Профиль: один пользователь на устройство, без авторизации
- Единицы измерения: метрические (кг, см, мл, ккал) — без переключателя на имперскую систему
- Адаптивная вёрстка под телефон
- Тема: светлая/тёмная с учётом системной настройки, акцентные цвета — синий и зелёный

## Модуль 1: Норма калорий

### Уже реализовано
- Расчёт суточной нормы (TDEE) по формуле Mifflin-St Jeor
- Учёт пола, возраста, веса, роста, уровня активности и цели (похудение / набор / поддержание)
- Базальный обмен (BMR)
- ИМТ с категорией (Недовес / Норма / Избыток / Ожирение)

### Новое: логика цели и защитные пороги
- Пресеты темпа изменения веса вместо произвольного ввода процента:
  - Медленно: ≈250 ккал/день (≈0.25 кг/неделю)
  - Умеренно: ≈500 ккал/день (≈0.5 кг/неделю)
  - Быстро: ≈750 ккал/день (≈0.75 кг/неделю)
- Защитный минимум калорийности: не ниже 1200 ккал (женщины) / 1500 ккал (мужчины), даже если выбранный пресет при низком TDEE формально даёт меньше
- При срабатывании защитного порога — предупреждение в интерфейсе («для более быстрого похудения проконсультируйся с врачом или диетологом»), а не молчаливое обрезание цифры
- Симметричный кап на профиците — не позволять подбирать неоправданно большой избыток

### Новое: расчёт БЖУ
- Авто-расчёт по умолчанию: белок в граммах на кг массы тела (≈1.6–2.2 г/кг в зависимости от цели — выше при похудении и наборе мышечной массы, ниже при поддержании); жир — от массы тела или % калорий; углеводы добивают остаток калорийности
- Ручной режим: переключатель, позволяющий ввести граммы БЖУ самостоятельно
- При расхождении ручного ввода с целевой калорийностью — предупреждение, без блокировки сохранения

## Модуль 2: Дневник питания

### Уже реализовано
- Записи по приёмам пищи: завтрак, обед, ужин, перекус
- Навигация по датам (вперёд/назад)
- Прогресс-бар к дневной калорийной цели
- Трекер воды (стаканы по 250 мл, цель 8 в день)

### Новое: разбор еды текстом (AI)
- Провайдер: **Groq API**, бесплатный тариф
  - Gemini рассматривался первым, но отклонён: бесплатный тариф Gemini API недоступен пользователям из ЕЭЗ, Швейцарии и Великобритании по условиям использования — только платный
  - У Groq аналогичного регионального ограничения в условиях использования не обнаружено
- Endpoint: `https://api.groq.com/openai/v1/chat/completions` (OpenAI-совместимый формат запроса)
- Авторизация: `Authorization: Bearer $GROQ_API_KEY`
- Модель: `openai/gpt-oss-20b` (быстрее и дешевле llama-3.3-70b-versatile, есть встроенное рассуждение) — `llama-3.3-70b-versatile` как более обкатанная альтернатива; смена модели — один параметр в коде
- Режим структурированного JSON-ответа: пользователь вводит текст вроде «омлет из 3 яиц и тост с маслом», модель возвращает массив объектов `{продукт, граммы, ккал, белки, жиры, углеводы}`, который парсится в записи дневника
- Вызов API — напрямую с фронтенда (без бэкенда); ключ хранится в `.env`; ссылка на деплой не публикуется широко (снижает риск компрометации ключа при отсутствии прокси-сервера)

### Новое: учёт порций
- Граммы — основная единица хранения (база продуктов хранит значения на 100 г) и ввода количества
- Опциональные быстрые порции на уровне конкретного продукта (например, «1 шт ≈ 50 г» для яиц, «1 кусок ≈ 30 г» для хлеба)

### Новое: напоминания
- Визуальные, внутри приложения — баннер/бейдж при открытии (например, «вода: 2 из 8 стаканов», «ужин не записан»)
- Push-уведомления не реализуются: архитектура без бэкенда и сервис-воркера их не поддерживает

## Модуль 3: Статистика

### Уже реализовано (без изменений)
- Столбчатый график калорий за последние 7 дней
- Линия дневной цели, выделение сегодня, среднее за дни с записями

## Модуль 4: База продуктов

### Уже реализовано
- 20 предзагруженных продуктов
- Поиск, добавление, редактирование, удаление

### Новое: пополнение базы через AI
- При добавлении нового продукта пользователь вводит только название
- Тот же Groq API подставляет калорийность и БЖУ на 100 г (тот же вызов, что и для дневника, другой промпт)
- Предложенные значения можно поправить вручную

## Модуль 5: Резервное копирование (новое)

- Автоматическое скачивание JSON-файла со всеми данными localStorage при первом открытии приложения за календарный день
- Ручной экспорт/импорт JSON-файлом — для миграции на новое устройство или после очистки браузера
- Рассмотрена и отклонена для v1: File System Access API (тихая запись без скачиваний) — не поддерживается в Firefox и Safari, оставлена как возможное улучшение

## Эксплуатационные заметки

- Ключи Groq API требуют обязательного указания срока действия при создании, максимум 90 дней — постоянных ключей нет
- Нужно вручную перевыпускать ключ и обновлять `.env` примерно раз в 80 дней; рекомендуется завести повторяющееся напоминание в личном календаре (вне приложения — это забота разработчика, не пользовательский функционал)
